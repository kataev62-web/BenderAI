## Что исправлено по реальным Windows-запускам

1. Крупные кванты `monotonic()` в Python 3.12/Windows приводили к потере событий сразу после resume. Для записи используется общий высокоточный `perf_counter()`, интервалы паузы полуоткрытые, живые события на паузе исключаются по состоянию. Добавлен воспроизводимый регрессионный тест с грубыми часами.
2. pywin32 CreateJobObject требует Unicode-имя; для анонимного объекта используется пустая строка вместо None. Утверждённый нативный subprocess теперь проходит Windows-тест. Реальный JDK/Gradle-проект этим не проверяется.
3. `win32process.QueryFullProcessImageName` отсутствует в закреплённой pywin32. Используется документированный `kernel32.QueryFullProcessImageNameW` с ограниченными правами процесса, точными ctypes-сигнатурами и закрытием handle; отдельный Windows-тест проходит.
4. Кириллические ошибки могли ломать отчёт CI при ASCII/Windows-кодировке. Отчёты/аннотации явно UTF-8; ключеподобные строки маскируются. Ошибки не скрываются, тесты не отключались.
5. Frozen bootstrap вызывает freeze_support до импорта GUI. Smoke-test ограничен 60 секундами, пишет JSON ошибки вместо ожидания скрытого traceback-диалога и сохраняет handle процесса для надёжного чтения exit code.

Ранние неуспешные запуски остаются в истории Actions; успешные ссылки выше соответствуют исправленному коду. Проект опубликован прямым обычным push, без force-push. Отдельный PR не требовался.

## Что действительно проверено функционально

- Парсинг офлайн-команд и строгие планы; запуск команды не происходит на этапе планирования; двойное выполнение блокируется.
- Создание папки только после разрешения и подтверждения; отказы путям вне разрешённого корня; Windows/Linux сохранение настроек/навыков/версий.
- На Win32-форме: запись несекретного ввода как параметра, запись Invoke кнопки, сохранение, закрытие/открытие базы, исполнение с другим значением, проверка текста статуса. Перемещение кнопки при том же ID не ломает навык. Неверный ID останавливает исполнение.
- Отказ UIA-ввода в password-поле, отсутствие демонстрационного значения в параметризованном навыке, запрет доступа к неразрешённому активному окну.
- Кооперативный стоп очереди/ожидания, отмена до старта worker и жёсткий таймаут изолированного процесса; сохранение статусов без введённых значений.
- Сам **упакованный exe запускается в Windows CI**, а не только исходники Python.

## Пока не проверено на настоящем рабочем столе

Оригинальный персонаж поверх рабочих окон, клики сквозь маску, трей, глобальный stop/hotkey и конфликт сочетаний, автозапуск HKCU, несколько физических мониторов/mixed DPI, полноэкранные программы, закрытие упакованного приложения во всех состояниях, ввод человеком и полный цикл обучения через редактор внутри готового exe. Нужна ручная приёмка по ссылке выше на обычном Windows 10/11 x64 ПК без прав администратора.

Открытие реальных Блокнота/Калькулятора/Проводника из готового GUI не проверялось автоматически. Подключение настоящих Ollama/облачного API, хранение настоящего ключа в Credential Manager, реальный Gradle/JDK-проект, снимки экрана и пользовательские PNG-пакеты требуют отдельных проверок. Нет оснований объявлять их работающими по одному CI-тесту парсера.

Голос, OCR/универсальное зрение, любые сайты/программы, планировщик автономных действий, платежи и интеграция Kingdom не реализованы и в этот этап не добавлялись.

## Как запустить полученный ZIP

1. Войти в GitHub при необходимости и скачать артефакт по ссылке выше.
2. Распаковать внешний архив артефакта и вложенный `BenderAI-windows-x64.zip`.
3. Запустить `BenderAI.exe` из полной распакованной папки, без повышения прав.
4. Начать с offline и пустой тестовой папки. Обучение проверять на `BenderTraining.exe` через «Навыки → Открыть тестовую форму».
5. Выполнить [ручной чек-лист](WINDOWS_MANUAL_TEST.md), зафиксировать SHA из BUILD-INFO и фактические pass/fail/not run.

Итог: **создан и опубликован запускаемый Windows-кандидат с успешными автоматическими проверками**. Подтверждение всех интерактивных сценариев на пользовательском Windows-компьютере ещё требуется. Новых крупных функций до этой приёмки не начинали. Публикация облачной среды не выполнялась, временное предложение добавить api.github.com отменено; сетевые настройки возвращены к исходным.
