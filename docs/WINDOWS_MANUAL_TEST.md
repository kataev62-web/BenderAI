# Приёмка на настоящем Windows-компьютере

Цель: проверить базовое приложение, а не добавлять новые функции. CI/offscreen/COM smoke-test **не заменяют** этот протокол. Пока запись результатов на реальном ПК отсутствует, перечисленные интерактивные функции остаются непроверенными.

## Подготовка

- Windows 10/11 x64, обычная учётная запись без запуска от администратора. Для воспроизводимости используйте отдельный тестовый профиль.
- На странице GitHub Actions выберите успешный запуск для нужного **commit SHA**. Скачайте артефакт `BenderAI-windows-x64`. Внешний архив артефакта может содержать `BenderAI-windows-x64.zip`: распакуйте и этот ZIP в отдельный каталог.
- Оставьте рядом `BenderAI.exe`, `BenderTraining.exe`, каталог `_internal`, лицензии и остальные файлы. Не запускайте приложение непосредственно из ZIP и не переносите один exe.
- Сохраните SHA коммита, ссылку Actions, SHA256 скачанного архива (`Get-FileHash ... -Algorithm SHA256`), версию Windows, разрешения/масштаб экранов. Сборка пока не подписана и не является публичным сертифицированным релизом.
- Создайте пустую папку для экспериментов, например `C:\Bender-Test`. Не используйте реальные документы, пароли, платёжные сайты и почту.
- Предыдущую базу не удаляйте: при закрытом приложении сохраните резервную копию `%LOCALAPPDATA%\BenderAI\memory.db`. В новом профиле база будет отдельной.

## Автоматический smoke-test на этом компьютере

Из PowerShell в распакованном каталоге:

```powershell
$p = Start-Process -FilePath .\BenderAI.exe -ArgumentList '--smoke-test','--native-smoke' -PassThru
if (!$p.WaitForExit(60000)) { Stop-Process -Id $p.Id; throw 'Smoke-test timed out' }
if ($p.ExitCode -ne 0) { throw "Smoke-test failed: $($p.ExitCode)" }
```

Smoke-test использует временную базу, открывает/закрывает Qt-окно и проверяет запуск изолированного UIA-адаптера с пустыми правами. Он **не проверяет** кликабельность реального рабочего стола, корректность записи демонстрации, визуальные анимации, hotkey, Credential Manager и многомониторность. При сбое зафиксируйте код/сообщение; не считайте сборку прошедшей.

Если доступны исходники и Python 3.12 x64, установите зависимости по README и выполните отдельно:

```powershell
$env:BENDER_WINDOWS_INTEGRATION = '1'
.venv\Scripts\python.exe -m pytest -m windows -v
```

Не запускайте интерактивные тесты в заблокированной сессии/RDP после отключения и не называйте такой пропуск успехом.

## Ручные сценарии

| № | Действия | Ожидаемый результат |
|---|---|---|
| 1 | Запустить BenderAI.exe, второй раз запустить его же | Оригинальный робот и русский чат; второй экземпляр не создаёт вторую очередь |
| 2 | Подождать, перетащить робота, открыть настройки, изменить размер/скорость, закрепить | Плавное движение, drag, остановка движения; настройки сохраняются после перезапуска |
| 3 | Нажимать рядом с силуэтом, включить «Не мешать», открыть чат через трей | Клики вне маски проходят к окнам; в «Не мешать» персонаж пропускает клики, трей остаётся доступен |
| 4 | Скрыть персонажа через трей и вернуть; закрыть чат и открыть через трей | Окна/персонаж показываются и скрываются; закрытие чата не теряет управление |
| 5 | Выбрать offline; ввести «Открой Блокнот», затем «Выполнить» дважды | До выполнения ничего не открывается; после — один запуск, результат/ошибка понятны |
| 6 | «Открой калькулятор», «Открой папку Загрузки» | Соответствующее приложение/папка доступны; нет запуска неизвестной команды |
| 7 | Разрешить чтение Блокнота, открыть его, запросить «Что сейчас открыто?» | Чат кратко скрывается; после разрешения показывается допустимая сводка предыдущего окна. Для неразрешённого окна — отказ |
| 8 | Разрешить запись только в C:\Bender-Test; «Создай папку \"Demo\" в \"C:\Bender-Test\"» | Отказ от подтверждения не создаёт папку; подтверждение создаёт её и фиксирует success |
| 9 | Запросить создание в другом каталоге и через путь за пределами разрешённого | Отказ, без изменения файлов. Приложение не удаляет/перемещает файлы |
| 10 | «Навыки» → открыть тестовую форму → «Бендер, учись» → выбрать BENDER AI Training | Запуск и доступ требуют согласия; до красного индикатора записи демонстрацию не начинать |
| 11 | Оставить текст параметрами, ввести Alice в Name, нажать Greet; остановить запись | В таблице есть ввод `${value_1}` и нажатие `1002`, отсутствует буквальное Alice |
| 12 | Добавить assert для `1003`, тип Text, `text:Hello Bob`; сохранить | Навык сохраняется после подтверждения, появляется версия v1 |
| 13 | Перезапустить приложение, открыть тестовую форму, выбрать навык → «Проверить» → выполнить с value_1=Bob | Имя вводится, Greet вызывается, статус Hello Bob, проверка success и журнал всех шагов |
| 14 | В форме Move button, повторить навык | Greet найден по AutomationId на новой позиции, результат тот же |
| 15 | В копии навыка заменить ID кнопки на несуществующий и запустить | Ошибка поиска, следующие шаги skipped; никакого клика по старому месту |
| 16 | В новой демонстрации вводить в Password; сделать действие в другом окне; пауза/продолжение | Пароль и события чужого окна/интервала паузы не входят в сохранённые шаги/экспорт |
| 17 | Создать сценарий ожидания отсутствующего элемента (timeout=30), за ним безопасное действие; выполнить и нажать СТОП | Ожидание прекращается, следующие шаги не выполняются, статус cancelled; GUI отвечает |
| 18 | Повторить стоп кнопкой трея и Ctrl+Alt+F12; занять сочетание другим ПО | Стоп действует; при конфликте клавиши выводится ошибка, доступна альтернативная Ctrl+Shift+F12 |
| 19 | Изменить навык, сохранить v2, восстановить v1, экспортировать/импортировать JSON | История версий сохраняется; откат создаёт новую версию; импорт ничего не запускает/не выдаёт права |
| 20 | Просмотреть и очистить журнал; удалить тестовый навык | История очищается; выбранный навык и версии удаляются только после подтверждения |
| 21 | Выбрать Ollama без запущенного сервера; отправить команду | Понятная ошибка/таймаут, GUI остаётся отзывчивым; можно вернуться в offline |
| 22 | Не включать облако, не выдавать screenshot | Нет запросов облака/фоновых снимков. Отдельный screenshot требует нового согласия, выбора экрана и пути |
| 23 | При наличии второго монитора переместить робота; изменить DPI и отключить дисплей | Персонаж возвращается в доступную область, не исчезает за границами. Если второго экрана нет — отметить not run |
| 24 | Закрыть приложение во время ожидания/записи, затем запустить снова | Процессы записи прекращаются; база открывается; нет самопроизвольного продолжения старого запуска |

Необязательные проверки с отдельными данными: настоящее облако/ключ в Credential Manager; автозапуск Windows; доверенный Gradle/JDK-проект; локальный character pack. Их нельзя считать прошедшими только потому, что основной smoke-test успешен.

## Форма результата

```text
Commit / Actions URL / ZIP SHA256:
Windows edition/build, x64:
Monitors / DPI:
Packaged smoke-test: pass / fail / not run, exit code:
Native pytest: passed / failed / skipped / not run (точные числа):
Сценарии 1–24: для каждого pass / fail / not run + наблюдение:
Приложение не закрывается / ошибки / процессы после выхода:
Что воспроизводится после чистого запуска:
```

При ошибке приложите только тестовые значения и безопасные сообщения. Не отправляйте API-ключи, пароли, базу с личными навыками или скриншоты личных документов. Наличие хотя бы одного неисполненного сценария означает «не проверено», а не «работает».
