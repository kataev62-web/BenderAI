# BENDER AI

Локальный визуальный помощник для Windows 10/11 x64. Оригинальный рисованный робот, русский интерфейс, офлайн-команды, явные разрешения и навыки по демонстрации. Рабочее имя; ресурсы «Футурамы» не используются.

**Статус: кандидат 0.3.0 локального помощника для ручной Windows-приёмки.** [Текущая Windows CI и ZIP](https://github.com/kataev62-web/BenderAI/actions/workflows/windows.yml?query=branch%3Acodex%2Fissue-4-voice-avatar-explorer-20261108). Проверки реального ПК и Ollama: [инструкция](docs/USER_GUIDE_RU.md). [Исторический отчёт базовой версии 0.1](docs/WINDOWS_BUILD_REPORT.md).

## Запуск в Windows

Нужен Python **3.12 x64** (с python.org), обычная интерактивная сессия без прав администратора.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -c constraints.txt -e ".[dev]"
.venv\Scripts\python.exe -m bender_ai
```

Либо `powershell -File scripts/run_dev.ps1`. Ollama, VPS и облачный ключ не нужны. Приложение не скачивает модели. Данные: `%LOCALAPPDATA%\BenderAI\memory.db`. Автозапуск и облако по умолчанию выключены.

### Локальная модель Ollama (без облачных API)

Для ПК с 4 ГБ видеопамяти можно начать с [Qwen2.5 Coder 3B](https://ollama.com/library/qwen2.5-coder:3b) (загрузка модели ~1,9 ГБ):

```powershell
ollama pull qwen2.5-coder:3b
ollama list
```

Затем в BENDER AI откройте **Настройки → ИИ → ollama**, проверьте имя модели `qwen2.5-coder:3b` и сохраните. Ollama должна быть запущена на `http://127.0.0.1:11434`. API-ключ и разрешение на облачную сеть не требуются. Бендер не скачивает модель автоматически; для действий на ПК по-прежнему нужны права и подтверждение. Ollama используется отдельно для естественного разговора и для предложения структурированных планов; разговор не имеет доступа к инструментам ОС. Локальная модель может ошибаться, поэтому проверяйте предложенный план.

Офлайн-команды: `Открой Блокнот`, `Открой калькулятор`, `Открой папку Загрузки`, `Что сейчас открыто?`, `Покажи мои навыки`, `Остановись`. Создание папки: `Создай папку "Отчёты" в "C:\Работа"` — предварительно разрешите каталог во вкладке «Разрешения». Новая команда сначала становится планом; кнопка выполнения и подтверждение изменений обязательны.

## Локальные команды и Ollama

В настройках выберите «Офлайн» или «Локальный ИИ — Ollama». Простые команды всегда обрабатываются правилами; неизвестная команда в режиме Ollama делает один запрос к `127.0.0.1:11434`, модель по умолчанию `qwen2.5-coder:3b`. Кнопка проверки показывает доступность сервера и наличие модели. СТОП прерывает изолированный запрос; автоматических повторов нет. Настройки сохраняются. Платные API автоматически не включаются.

Дополнительно офлайн: `Прочитай файл "C:\Работа\заметка.txt"`, `Создай файл "C:\Работа\новая.txt" с текстом "Привет"`, `Скопируй файл "C:\Работа\заметка.txt" в "C:\Работа\копия.txt"`. Нужны разрешённые каталоги; поддерживаются данные .txt/.md/.csv/.json/.log, чтение UTF-8 до 64 КиБ, копирование до 8 МиБ. Создание/копирование требуют подтверждения и не перезаписывают существующие файлы.

Для стороннего приложения выберите его окно в разрешениях и отдельно «Чтение, управление и запуск». Команда `Открой приложение "writer.exe"` использует только сохранённый путь EXE, без аргументов. Консоли/интерпретаторы не разрешаются этим механизмом. Сохранённый навык: `Выполни навык Название` — сначала предпросмотр, параметры и подтверждение.

Если запуск был передан ОС, но окно не подтверждено, результат показывается как «Не подтверждено» и следующие шаги останавливаются. Автоматического повторного открытия нет.

## Межоконное обучение

Запись поддерживает несколько явно разрешённых окон Windows: точные разрешения по EXE/заголовку, переходы с ожиданием/фокусом, текстовые параметры, Invoke, SelectionItem, Toggle и ExpandCollapse при наличии UIA Pattern. Перед запуском нужен просмотр и подтверждение плана. Браузеры/консоли пока требуют отдельного адаптера.

[Пошаговая инструкция, ограничения и ручная Windows-приёмка](docs/MULTIWINDOW_LEARNING_RU.md).

## Обучение без программирования

1. «Навыки» → «Открыть тестовую форму». Подтвердите запуск и доступ.
2. «Бендер, учись» → отметьте **BENDER AI Training** (и другие явно разрешённые окна). Оставьте текст параметрами. Дождитесь красной надписи **«Запись действий включена»**.
3. В форме введите имя в **Name**, нажмите **Greet**. Парольное поле исключено.
4. Вернитесь в приложение → «Стоп и редактировать». Откроется таблица шагов. Параметр `${value_1}` — значение при запуске.
5. Выберите шаг → «Добавить проверку», измените AutomationId на `1003`, тип на `Text`, ожидаемое состояние на `text:Hello Bob`. Сохраните с подтверждением.
6. «Навыки» → «Проверить» → «Выполнить показанный план», значение `value_1` = `Bob`. Это реальное выполнение, не имитация.
7. В форме нажмите **Move button** и повторите навык: поиск идёт по ID, не по старым координатам. После перезапуска приложения навык остаётся в базе.

**СТОП:** кнопка в чате, трей или **Ctrl+Alt+F12** (настройка Ctrl+Shift+F12). При конфликте регистрации клавиши выводится ошибка. Текущая задача получает отмену; следующие шаги не запускаются. Уже доставленное ОС действие нельзя отменить задним числом.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest -m "not windows" -q
# Только в разблокированной интерактивной Windows-сессии:
$env:BENDER_WINDOWS_INTEGRATION = '1'
.venv\Scripts\python.exe -m pytest -m windows -v
```

Linux для разработки ядра/GUI: `python3.12 -m venv .venv`, `.venv/bin/python -m pip install -c constraints.txt -e '.[dev]'`, `QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q`. Без Windows нативные действия завершаются явной ошибкой, а не фиктивным успехом. `python -m bender_ai --smoke-test` открывает и закрывает Qt-окно с временной базой, без управления ОС.

## Windows-сборка

```powershell
powershell -File scripts/build_windows.ps1 -Python .venv\Scripts\python.exe
```

Результат при успешной сборке: `dist/BenderAI/BenderAI.exe`, `BenderTraining.exe` рядом с ним и **вся** папка `_internal`; переносимый архив `dist/BenderAI-windows-x64.zip`. Не переносите один exe без библиотек. Скрипт запускает тесты, PyInstaller и smoke-test упакованного приложения. CI `.github/workflows/windows.yml` публикует ZIP как артефакт успешного workflow, не как подписанный релиз. ## Разговор, микрофон и локальный импорт GLB (#4)

Одна строка и кнопка «Отправить»: «Авто» направляет вопросы в разговор Ollama, явные команды ОС — в проверяемый план. Для неоднозначного текста выберите «Разговор» или «План». Ответ модели в разговоре не может запустить инструменты. Простые команды работают без Ollama; модель и её качество на вашем оборудовании проверяются отдельно.

В настройках включите озвучивание, обновите список установленных SAPI-голосов и прослушайте тест. Автовыбор предпочитает русский мужской голос; доступный тембр зависит от установленных голосов Windows. Если русского голоса нет, ответ остаётся текстом с объяснением: автоматической загрузки TTS/имитации актёра нет. Можно явно выбрать другой установленный голос. СТОП завершает отдельный процесс речи; talk-анимация начинается по состоянию SAPI, физические динамики требуют ручной проверки.

Микрофон — локальный Vosk, необязательный. Windows ZIP включает runtime; при запуске из исходников установите `.[dev,voice]`. Самостоятельно выберите и распакуйте русскую модель Vosk с подходящей лицензией, укажите папку в настройках. Нажатие «Говорить» требует отдельного согласия и включает запись до 15 секунд. Распознанный текст появляется в общей строке без автоматической отправки. Модель не скачивается, звук не сохраняется и не передаётся в облако; СТОП закрывает процесс записи.

«Настройки → Импортировать GLB» принимает собственную локальную модель и установленный Blender. Импорт идёт в новый локальный пакет с таймаутом/отменой; только после проверки кадров включается персонаж. Это рендеринг 3D-модели в анимированные прозрачные PNG, **не интерактивная 3D-сцена**. Исходная фан-модель отсутствует в репозитории и не включается в ZIP. Используйте только модели с подходящими правами; сеть и внешние ресурсы GLB при импорте запрещены. В CI используется синтетическая геометрия.

Explorer использует отдельный Shell-адаптер для явно выбранного окна и разрешённой папки. Навигация и создание подпапки требуют соответствующих точечных разрешений; окно не даёт доступ ко всему диску. Кнопка обучения объясняет недостающие права. Наблюдаемое появление папки само по себе не доказывает действие пользователя: такие изменения требуют проверки; явная команда создания записывает только подтверждённый результат. Полная ручная приёмка: [руководство](docs/USER_GUIDE_RU.md) и [межоконное обучение](docs/MULTIWINDOW_LEARNING_RU.md).
